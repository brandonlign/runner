## Frozen method transported to MAARSY

P13 remains dual-output:

1. **Primary discovery core:** exact promoted recurrent-core architecture, with immutable core family generation and multiplicity ranking semantics. Primary discovery/qualification/recovery claims use the core only.
2. **Secondary characterization halo:** exact P12 characterization membership transported without retuning. The halo may improve membership characterization but cannot create, delete, reorder, rescue, or qualify a discovery-core family.

The following scientific constants/rules are inherited unchanged from the promoted development method wherever the external schema supports the required quantity: two-view observation/orbital representation, deterministic cross-year construction, P3 reliability constants (`0.5` seed-floor minimum, `0.10` negative-tail budget), P8 finite-sample rank derived from that same `0.10`, P9 reciprocal reliability, P4/P10 geometry, P11 density-contrast rule, P12 drift-conditioned representation, responsibility rule, no recursive growth, no halo reranking, and no parameter search.

If MAARSY lacks a required observable needed for an **exact** frozen scientific quantity, the run is `ARCHITECTURE_INCOMPATIBLE` rather than silently substituting another feature or retuning the method. Any scientifically different successor would require new target-excluded development; it cannot be chosen from the MAARSY result.

Before any MAARSY known-shower label value is indexed, the external workflow must freeze and hash:

## Power classification before success/failure

The external panel is scientifically **power-eligible** only if, after the frozen target exclusion and before interpreting method performance, the truth universe contains at least **5 known-shower labels with >=4 usable events in each of 2020 and 2021** and the frozen core produces at least **5 recurrent families**. These are minimum interpretability conditions, not tuning thresholds.

If either condition fails, verdict is `POWER_INCONCLUSIVE_MAARSY_2020_2021`. That is neither a method pass nor a method failure and does not authorize target access. It also does not permit retuning to MAARSY.

## No-retuning generalization gates

For a power-eligible panel, P13 passes external validation only if all of the following hold:

### Core discovery integrity

- exact core family/rank construction completes with no target/firewall/integrity violation;
- immutable core seeds are preserved;
- at least one externally truth-qualified recurrent shower is recovered by the core;
- no halo membership is used to define core qualification, core recovery, or core rank.

### Halo characterization generalization

Using the same eligible external known-shower set for core and halo:

- halo macro-F1 is at least **core macro-F1 + 0.08**;
- for externally large showers (same frozen definition as development, total usable truth members >=100 when that subset is nonempty), halo mean recall is at least **1.5×** core mean recall;
- when the external large-shower subset is nonempty, halo mean precision is at least **0.85**;
- if the large-shower subset is empty, the two large-shower gates are marked not-applicable and do not manufacture a pass; the macro-F1 and core-discovery gates still must pass.

These are inherited development effect-size/precision gates, fixed before MAARSY truth. No weaker MAARSY-specific substitute is allowed.

Final power-eligible verdict is `PASS_P13_MAARSY_2020_2021_NO_RETUNING_EXTERNAL` only if every applicable integrity/generalization gate passes; otherwise `FAIL_P13_MAARSY_2020_2021_NO_RETUNING_EXTERNAL`.
