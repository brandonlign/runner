# M2D SACV dual-output recurrent-core v1 — frozen protocol

## Motivation and ancestry

Binding target-excluded development established that replacing SACV v1 output by recurrence-first membership is not generically safe: full component union (#1411), one-pair extraction (#1409), edge-consensus (#1412), reciprocal-nearest (#1414), and fallback-only component replacement (#1417) all fail at least one frozen non-regression gate. These no-gos remain immutable.

The remaining diagnosed problem is role conflict rather than absence of recurrent structure. SACV v1 is already a passed primary extraction layer, but on its exact validation-failure path it returns the entire M2D parent. Recurrence-first all-hypothesis structure can define a narrower recurrent substructure, yet forcing that substructure to replace the primary output causes recall loss.

A dual-output architecture has genuine pre-OrbitTrace-reveal ancestry in promoted P13 (#670/#671): preserve a primary discovery/extraction output and evaluate a distinct nested membership view separately rather than forcing one set to satisfy both roles.

## Frozen scientific rule

For every exact frozen M2D parent, reconstruct the exact SACV v1 admissible local hypotheses, exact annual top-1 winners, exact reciprocal recurrence validation relation, recurrent graph, components, and inherited component ordering used in #1411/#1417. No physical metric, seasonal-analog null, contamination convention, radius set, support floor, recurrence gate, component selector, score, threshold, or tie-break changes.

Outputs:

1. **Primary extraction** — byte-equivalent SACV v1 semantics.
   - If the exact annual top-1 pair reciprocally validates, output the union of those two frozen SACV balls.
   - Otherwise output the entire M2D parent exactly.
   - Primary candidate rank/family identity remains the immutable M2D rank/family identity.

2. **Nested recurrent core** — available only on the exact SACV parent-fallback path.
   - If SACV top-1 validation fails but at least one unchanged all-hypothesis recurrent component exists, select `comps[0]` by the already-frozen component ordering and expose its natural hypothesis-membership union as `recurrent_core_ids`.
   - If no recurrent component exists, expose no core.
   - The core is nested metadata attached to the same parent. It is not a second ranked candidate and may not participate in primary literature matching, recovery counts, rank, MRR, or superiority claims.

No core is emitted for an already-successful SACV primary extraction. No threshold sweep, alternate component rule, nearest-neighbor rule, edge-consensus rule, core-size gate, or target-aware choice is authorized.

## GMN development gate

First binding scientific execution is the same target-excluded GMN Sugar2017/HDBSCAN2025 development benchmark. OrbitTrace target IDs/coordinates/memberships and SonotaCo scientific truth are forbidden.

Before truth opens, freeze all primary outputs and nested cores. Required integrity gates:

- primary output IDs must equal exact frozen SACV v1 output IDs for every candidate occurrence, not merely aggregate metrics;
- primary ranks/family identities remain unchanged;
- target/firewall and exact inherited geometry identities remain unchanged.

After the full pretruth seal, primary benchmark metrics must reproduce frozen SACV v1 exactly (within evaluator floating-point tolerance). This is an equality/integrity requirement, not a new superiority opportunity.

Nested-core utility is evaluated only as a secondary same-parent diagnostic. For each comparator route, among parent-recovered assignments that actually have a nested core, apply the inherited SACV same-parent utility standards when the inherited paired-count gate `n>=20` is met: nonempty fraction >=0.75, mean core precision >=0.80 and strictly greater than the corresponding primary/parent precision, mean core F1 >=0.75 times corresponding primary/parent F1, precision non-regression fraction >=0.50, and at least one strict refinement. Routes with fewer than 20 core-paired assignments are `POWER_INCONCLUSIVE`, not PASS evidence and not failure.

Development may be called a dual-output PASS only if primary equality is exact, at least one comparator route is core-power-eligible and passes every inherited core-utility gate, and no core-power-eligible route fails. Otherwise freeze the exact formulation as FAIL or POWER_INCONCLUSIVE as appropriate.

Only a valid development PASS may authorize an unchanged SonotaCo transfer. The nested core may never be used to inflate the primary literature benchmark by additional matching opportunities.

Any later OrbitTrace characterization is necessarily post-target-reveal evidence and cannot retroactively become pristine independent rediscovery evidence.
