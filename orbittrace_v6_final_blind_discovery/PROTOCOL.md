# OrbitTrace v6 final blind GMN discovery protocol — protocol-only freeze

## Status

This document preregisters the final target-containing blind GMN application of the frozen **v3-primary dual-output catalogue v6** architecture. It is a protocol/firewall freeze only. It does not execute the target-containing catalogue, does not load a withheld OrbitTrace reference, and does not authorize reveal.

This protocol activates only if v6 remains the promoted method after all preregistered upstream gates. If v6 fails development, or passes development but fails the frozen literature-superiority requirement and succession moves to P1/C1, this v6 blind protocol stays dormant and a successor method requires its own separately frozen blind protocol.

4. all source identities, result hashes, and integrity gates named by those stages verify exactly;
5. no successor architecture has superseded v6 under the preregistered succession rules.

The current intended authoritative development provenance is the strict semantic-replay recovery lineage rooted in exact-rescore run `31282128101`; the current canonical recovery execution is `31285583731`. If that recovery emits only a technical/equivalence failure and no scientific v6 verdict, no downstream authorization exists. ## 8. Exact v3 rescoring and primary membership

## 9. Components, recurrence, and family construction

## 10. Exact primary ranking

The complete primary list uses the exact emitted ordering of frozen `build_family_track_v6(..., "v3")`. Its scientific ranking terms are, in order:

## 12. Two-stage reveal firewall

### Stage A — blind catalogue discovery

Stage A receives the target-containing GMN corpus but **no withheld OrbitTrace reference**. It produces and immutably seals the complete primary v3 family ranking plus the separate rescue queue.

The Stage A artifact must state `withheld_reference_loaded=false` and record canonical SHA-256 digests of the complete ranked primary payload, rescue payload, source manifest, environment, and monthly inputs.

### Stage B — reveal

Stage B is a separate process/workflow that first verifies the complete immutable Stage A artifact and ranked-primary SHA-256. Only after those checks may it receive a separately sealed withheld-reference bundle.

The withheld-reference interface contains only stable GMN event/trajectory IDs and event years. Stage B cannot import detector, calibration, catalogue, centroid, component, family, membership, scoring, or ranking modules. It performs set intersection and the fixed classifications below only.

No family may be merged, split, expanded, reassigned, rescored, reranked, or shifted after reference access.

## 13. Exact reveal matching and inherited rank depths

Matching tolerance is zero: only exact stable GMN event-ID equality counts as overlap.

Radiant, speed, orbit, activity timing, D-criterion, coordinate tolerance, historical HDBSCAN assignments, or nearest-neighbor proximity cannot rescue a failed exact-ID match.

The positive rank depths are inherited from the earlier pre-reveal firewall and are frozen here without using any historical OrbitTrace recovery result:

- full primary blind recovery requires rank `<=25`;
- partial primary blind recovery requires rank `<=100`;

## 14. Frozen primary recovery classifications

## 15. Rescue-channel boundary

This boundary is frozen before target access specifically to prevent a sparse rescue result from becoming a post-hoc substitute for the method that passed the upstream primary gates.

## 16. Claim boundary

A successful primary Stage B result would establish a **prospectively frozen, target-withheld blind recovery/rediscovery by the v6 operational pipeline**. It would not rewrite the historical origin of the OrbitTrace candidate and would not prove universal superiority across radar/optical survey regimes.

Because v6 uses a predeclared binary native-background calibration designation, a successful result must not be described as fully label-free or same-information algorithmic discovery. The defensible claim is target-withheld operational discovery using no target identity/reference and no mapped shower identity in detector/ranking stages.

If authorization relies on the SonotaCo 2017/2019 transfer rather than a genuinely pristine external panel, the validation claim must remain `architecture-pre-frozen no-retuning external transfer`, not pristine prospective validation.
