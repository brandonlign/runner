## Fixed scientific priority

The project objective is the strongest **scientifically defensible target-free** discovery method, not the largest development score in isolation. Therefore detector-input independence has priority over the native-background convenience bit.

The hierarchy is fixed now:

1. **If v6-LF passes its frozen development gates, v6-LF becomes the primary v6-family method.** This is true regardless of whether ordinary v6 also passes or has numerically larger development metrics.
2. **Ordinary v6 may become primary only if v6-LF receives a genuine frozen scientific no-go.** A technical failure, timeout, import error, artifact problem, or other infrastructure failure is not a v6-LF scientific no-go and must be repaired equivalently rather than used to fall back to ordinary v6.
3. **P1 may activate only if both v6-LF and ordinary v6 are scientifically rejected at development**, unless a later protocol frozen before those results establishes a logically stronger prerequisite. An ordinary-v6 failure alone is no longer sufficient while v6-LF remains scientifically live.
4. No comparison of unknown development metric magnitudes may override this ordering.

This changes only project-level method selection. It changes no detector parameter, score, threshold, calibration rule, proposal budget, recurrence rule, ranking rule, membership rule, benchmark criterion, or target firewall.

- If ordinary v6 finishes first and passes, matched-literature execution must wait until v6-LF has a genuine scientific development verdict.
