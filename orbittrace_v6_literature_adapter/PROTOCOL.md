# Catalogue-v6 exact-row literature adapter — frozen before benchmark execution

## Activation

This adapter is source-frozen before the repaired catalogue-v6 target-excluded development result is known. It may be scientifically executed only if the exact repaired development run returns `PASS_V3_PRIMARY_CATALOGUE_V6_DEVELOPMENT`.

A development failure permanently leaves this adapter dormant for v6. It may not be used to rescue, tune, or reinterpret a failed development method.

## Purpose

Run the exact v3-primary catalogue-v6 architecture on the already-frozen SonotaCo 2023/2025 exact-event-row universes used for pairwise comparison with:

- full catalogue HDBSCAN assignments; and
- full Sugar uncertainty retained-master assignments.

The competitor assignments define the allowed scan event IDs. No competitor is rerun or retuned.

This adapter implements the claim protocol frozen separately in PR #493. It does not change those superiority gates.

## Exact-row scan universe

For each comparator panel and year:

1. load the frozen competitor assignment file and verify its existing SHA-256;
2. take its complete event-ID set as the allowed v6 scan universe;
3. retrieve only those exact SonotaCo raw rows;
4. parse only solar longitude, radiant geometry, and geocentric speed;
5. fail if any requested event is missing/duplicated/unparseable or enters 20–55 degrees.

Thus the v6 primary families and the comparator are evaluated on identical event rows within each pairwise panel.

## Frozen calibration-reservoir semantics

Source-only audit of the original v6 support loader established that v6 scans all valid target-excluded events but creates its Mondrian null reservoir only from events whose native label is genuinely background/`SPORADIC`.

The exact-row adapter preserves that rule:

- before scoring, the already-frozen SonotaCo parser may be invoked only to identify native `SPORADIC` IDs;
- the wrapper retains only that binary event-ID set for calibration;
- mapped shower identity, `complex_key`, shower code, per-shower count, or any other shower-specific value is not returned to the detector adapter;
- unsupported/unmapped non-background shower tokens are not silently inserted into the null reservoir;
- calibration IDs must be a subset of the exact competitor scan universe;
- at least 1,000 calibration rows and at least 30 supported v6 calibration bins are required in each year.

This is not a new label-assisted detector rule: it reproduces the already-frozen v6 development calibration construction on a new transport.

## Pre-truth ranking freeze

For each HDBSCAN/Sugar panel, the adapter must complete:

- both yearly scans;
- v3 primary component construction;
- v3 recurrent family construction;
- exact primary ranking;

before common mapped shower truth is used for evaluation.

The complete primary-family payload, scan audits, panel identity, year set, and corpus namespace are canonical-JSON encoded and SHA-256 hashed. That hash is the pre-truth ranking freeze.

The fixed4 rescue family list is kept separate and cannot enter the primary payload, primary ranking, or any literature-superiority gate.

## Post-freeze common truth and evaluation

Only after the primary ranking hash exists may the existing exact-row common-truth parser be used to map shower identities.

Evaluation reuses the frozen exact-row definitions:

- same event rows and same common truth for v6 and comparator;
- annual reference showers require at least four members;
- best matching v6 family / comparator cluster chosen by F1, then the existing frozen tie-breaks;
- report macro F1, mean precision/recall, F1>0.5, F1>0.8, and size bins `4–9`, `10–24`, `25–49`, `50–99`, `100+`;
- report method-specific returned-family/cluster burden without inventing a common ranking for Sugar/HDBSCAN.

The broad/sparse superiority classifications are exactly those frozen in PR #493 and cannot be edited from the result.

## Integrity failures

Any mismatch in source hash, competitor assignment hash, archive hash, event-ID universe, target exclusion, calibration subset, calibration support, proposal budget, primary/rescue separation, or pre-truth ranking freeze is an integrity failure and produces no scientific superiority verdict.

No alternate exact-row subset, calibration rule, seed namespace, threshold, membership radius, proposal cap, family rule, or evaluation denominator may be tried after seeing a result.

## Target firewall

This adapter cannot access the OrbitTrace target interval or target identity. Even a literature-superiority pass does not authorize target deployment; the separately frozen external-generalization and final target-deployment requirements remain binding.
