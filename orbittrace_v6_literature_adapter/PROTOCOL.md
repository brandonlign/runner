## Frozen calibration-reservoir semantics

Source audit of original v6 established that all valid target-excluded events are scanned, while the Mondrian null reservoir contains only events labelled genuinely `SPORADIC`.

A second pre-data source audit (`31271717722`) proved the validated native SonotaCo 2023 and 2025 adapters use an identical background-token function:

`token == "" or no ASCII letter is present or token starts with "SPO"`.

The older validated parser's returned `sporadic` list additionally applies its episode-specific ESV filter. Catalogue-v6 does not have that ESV calibration exclusion. Therefore this exact-row adapter **does not use the parser's returned `sporadic` list for calibration**.

Instead, before scoring, a dedicated transport step may read only the native shower-token field for the already-fixed exact scan IDs and reduce it immediately to a binary native-background event-ID set using the source-audited rule above. It must obey all of the following:

- no IAU mapping is performed;
- no mapped shower identity or per-shower statistic is retained;
- no ESV rule is applied;
- unsupported/unmapped non-background tokens remain non-background and cannot enter calibration;
- every exact scan ID must have exactly one raw native token;
- only the resulting binary background-ID set crosses into the detector process;
- calibration IDs must be a subset of the exact scan universe;
- at least 1,000 calibration rows and at least 30 supported v6 calibration bins are required per year.

This is the closest transport of the already-frozen v6 null construction and avoids inheriting an unrelated fixed4 episode-quality rule.
