# EFN post-pretruth governance after recurrent-EOM v1

Binding pretruth run `31842380038` froze the complete label-free EFN 2017/2018 HDBSCAN hierarchy and candidate rankings before any `Shower` access.

The binding pretruth result has `mechanism_active=false`: vanilla EOM and recurrent-EOM selected the same eight hierarchy nodes. The frozen EFN validation gate requires the recurrent selected-node set to differ from vanilla, so a PASS is impossible regardless of the still-hidden shower labels. Because the frozen protocol gives power-inconclusive precedence if either year has zero eligible labeled showers, no official PASS/FAIL/INCONCLUSIVE labeled validation token is asserted without Stage 3.

## Decision

Do **not** open EFN `Shower` merely to evaluate a validation gate that can no longer pass. Preserve the label field unopened.

However, because the research process has now observed EFN's unlabeled event geometry and hierarchy-level method behavior, EFN 2017/2018 is **not pristine external validation for any scientific successor designed after this observation**. It may not be used to claim independent validation of a post-recurrent-EOM successor, even if the shower labels remain hidden.

Any successor design after this point must be developed/frozen using only already-authorized development resources (permanent target-excluded GMN 2022+2023 and, only after development success, exposed SonotaCo 2013/2014). The EFN pretruth result, node identities, event geometry, candidate memberships, and rankings may not be used to tune or select successor parameters/features/rules.

The still-hidden EFN labels may be retained for archival use or for a future protocol that does not claim pristine independence, but they are not a clean external validation resource for newly designed successors.

Firewall remains:
- EFN `Shower` accessed: false
- OrbitTrace target information/events accessed: false
- protected target-region events/physical values accessed: false
- MAARSY scientific access: false
- DMS scientific access: false
